## 二、HeliosLM v1.0 現狀分析

### 2.1 項目聲稱 vs 實際代碼驗證

| 聲稱項目 | 聲稱值 | 實際代碼驗證 | 差距評估 |
|---------|--------|-------------|---------|
| **總參數量 (Ultra)** | 2.8T | `hidden_size=12288, layers=80, experts=256` 實際計算約 **4.21T** | ⚠️ 配置與聲稱差距 1.5x |
| **激活參數 (Ultra)** | 未說明 | 8/256 專家激活, 實際約 **213B** | ❌ 真實Kimi K3僅~32B激活, 差距6.7x |
| **上下文長度** | 1M (Ultra) | `max_position_embeddings=1048576` | ✅ 配置正確 |
| **速度目標** | 250 tok/s | 無CUDA內核優化, 無FlashAttention底層實現 | ❌ 純PyTorch無法達成 |
| **SWE-bench** | 95% | 僅有模擬測試框架, 無真實評估 | ❌ 無法驗證 |
| **GPQA Diamond** | 96%+ | 無訓練數據, 無預訓練權重 | ❌ 無法驗證 |
| **多模態** | ViT+Conformer | 基礎PyTorch實現, 無預訓練 | ⚠️ 架構存在但無法運行 |
| **定價** | $3/$15 | 無託管服務, 無API | ❌ 僅為理論定價 |
| **代碼規模** | 生產級 | 1,711行Python (含舊模塊), 無訓練腳本 | ⚠️ 原型框架級別 |
| **預訓練權重** | 宣稱開源 | ❌ 無任何權重文件 | 🔴 致命缺陷 |

### 2.2 關鍵架構問題

1. **參數計算不匹配**: Ultra配置(hidden=12288, 80層, 256專家)實際約4.2T總參數, 但真實Kimi K3為2.8T。激活參數(213B)遠超真實模型的~32B, 導致推理成本極高。

2. **無分布式訓練支持**: 無FSDP/DeepSpeed/Megatron集成, 無法訓練>1B模型。

3. **Stub代碼殘留**: `safety_alignment.py`等舊模塊中的ConstitutionalRuleEngine仍返回固定值, 需清理。

4. **無Tokenizer/數據管道**: 基礎設施缺失, 無法進行任何實際訓練。

## 五、Roadmap 2027-2028

### Phase 1: 基礎修正（2026 Q4 - 2027 Q1）— 從「概念」到「可運行」

#### 5.1.1 修正參數配置
```python
# 當前配置（~4.2T總, ~213B激活）
hidden_size=12288, num_experts=256, layers=80, activated=8

# 修正為真實2.8T規模（參考DeepSeek V4 / 真實Kimi K3）
hidden_size=12288, num_experts=256, layers=60, activated=8, expert_hidden=4096
# 總參數 ≈ 2.8T, 激活 ≈ 35B
```

#### 5.1.2 清理殘留Stub代碼
- [ ] 刪除或重寫 `safety_alignment.py`（ConstitutionalRuleEngine返回固定值）
- [ ] 刪除或重寫 `multimodal.py`（舊版基礎實現）
- [ ] 刪除或重寫 `adaptive_reasoning_v2.py`（MCTS使用隨機噪聲）
- [ ] 統一所有模塊接口

#### 5.1.3 引入基礎設施
| 組件 | 推薦方案 | 原因 |
|------|---------|------|
| 分布式訓練 | **Megatron-LM** 或 **DeepSpeed** | 必須支持TP/PP/EP |
| 注意力優化 | **FlashAttention-3** | 必須, 否則無法訓練長上下文 |
| 量化訓練 | **FP8/BF16混合精度** | 降低顯存佔用 |
| 數據管道 | **WebDataset** + **MosaicML Streaming** | 萬億token級別數據加載 |
| Tokenizer | **SentencePiece** (多語言) | 與真實Kimi生態兼容 |

### Phase 2: 預訓練數據與訓練（2027 Q1-Q3）— 從「可運行」到「有智能」

#### 5.2.1 數據策略

| 數據類型 | 比例 | 來源 | 處理 |
|---------|:----:|------|------|
| 網頁文本 | 60% | Common Crawl + 中文語料 | 質量過濾、去重、毒性過濾 |
| 代碼 | 20% | GitHub + StackOverflow | 語言分類、許可證過濾 |
| 學術/書籍 | 10% | arXiv + 電子書 + 維基百科 | 數學公式LaTeX保留 |
| 多模態 | 5% | 圖文對 + 視頻字幕 | 對齊處理 |
| 合成數據 | 5% | 高質量模型生成 + 驗證 | 用於推理和對齊 |

**總量目標: 15-20T tokens**

#### 5.2.2 訓練階段

```
階段1: 預訓練 (3-4個月)
- 數據: 15T tokens
- 序列長度: 4K -> 32K -> 128K 漸進
- 計算: ~50,000 H100 hours (約$1.5M)

階段2: 長上下文擴展 (1個月)
- YaRN/NTK擴展: 128K -> 1M
- 繼續預訓練 + 位置編碼調整

階段3: 監督微調 (1個月)
- 高質量指令數據: 10M+ 對話
- 領域覆蓋: 編碼、數學、科學、創意寫作

階段4: RLHF/DPO (1個月)
- 偏好數據收集
- PPO/DPO訓練
- 安全對齊數據

階段5: 工具使用與Agentic (1個月)
- Function calling數據
- 多步推理軌跡
- MCP工具鏈集成
```
