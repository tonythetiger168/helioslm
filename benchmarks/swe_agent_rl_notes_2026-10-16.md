## 找到並修掉的問題

1. **錯誤 DONE 不扣分 → 「套用就停」免費拿 1/3。** 加入 `--false-done-penalty`。
2. **環境太慢（每次更新約 300 秒）。** 改成依「首次套用順序、去重複」的 patch 序列記憶沙盒結果；第一版用「集合」當 key 是錯的（正解改到檔尾那行時，順序會影響結果），T100 抓到後修正，並在 20 題 × 27 條序列上與真實沙盒逐一比對 0 誤差。現在每次更新約 4–8 秒。
3. **log-prob 不一致（真 bug）。** rollout 記錄的是「只限動作 token」的 log-prob，GRPO 重算的是全詞表 log-prob，ratio 從一開始就遠小於 1；PPO clip 下 `min(r·A, 0.8·A)` 在 A < 0 時取常數，**負 advantage 完全沒有梯度**。改成全詞表後，T100 檢查 ratio 恰為 1。

## 診斷：為什麼修完仍學不會

修正後的 4 組都在 10–20 次更新內坍縮成「永不 DONE」（重複套用同一個 patch 直到步數用盡），連 lr 1e-4 也一樣。

- **探索不足：** 正確流程（套對 → TEST → 看到 PASS → DONE）在隨機策略下很少出現；DONE 大多出現在錯誤時機，平均是壞的，於是 DONE 的機率被**整體**壓低——包括看到 PASS 之後的 DONE。策略來不及學會依觀測決定何時停。
- **序列級功勞分配：** advantage 是整條軌跡共用，10 步軌跡的梯度量是 2 步的 5 倍（log-prob 總和），偏向長軌跡。
