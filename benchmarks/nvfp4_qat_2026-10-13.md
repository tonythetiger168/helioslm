# B1-3 — NVFP4 QAT 端到端訓練 smoke（2026-10-13）

NVFP4 QAT 目標（v5.22-L 起在 `qat.py`：E2M1 值 × 16 寬 block、E4M3 block scale、
per-row fp32 上層 scale、STE 梯度回 fp32 主權重）首次端到端訓練驗證，對齊 NVIDIA
NVFP4 硬體路線（Blackwell）。三臂共用同一語料快照、同一 val 協議、同一 seed 與
資料順序（train_toy_checkpoint 配方：Adam + cosine、MTP aux loss 0.3），唯一變因是
NVFP4 grid 進入的位置。機器可讀結果：
[`nvfp4_qat_2026-10-13.json`](nvfp4_qat_2026-10-13.json)，
`results_sha256 = 02329ef5b2605d74c29dfd7325450c90739f9be20d111a6c93790502dfc6b3c7`。

## 結果（每臂 240 步 char-LM 訓練，batch 8 × seq 64，seed 13，CPU，lite 8.5M from scratch）

| arm | val_loss | vs fp32 | 說明 |
| --- | --- | --- | --- |
| fp32_scratch | 2.5416 | — | 品質參照臂 |
| ptq_rtn_nvfp4 | 2.5361 | **-0.0054** | RTN 直接上 grid，零額外訓練 |
| qat_nvfp4 | 2.5995 | +0.0579 | grid 從 step 0 進訓練迴圈（STE），55 個 Linear 全包 |

**三個正確性 oracle 全部通過**：

1. **deploy parity = EXACT**：STE wrapper 前向與 bake 後純 nn.Linear 模型的 val loss
   **bitwise 相等**——bake 不掉任何資訊，`FakeQuantLinear` 的前向值就是 NVFP4 kernel
   的重建值，baked 模型即 deploy 模型，不需新增 serving 模組。
2. **bitwise gate = PASS**：QAT 臂同 seed 重跑，baked val loss、final train loss、
   greedy probe token 三者完全一致。
3. **收斂 oracle = PASS**：QAT 訓練 loss 4.340 → 2.730 單調下行；deploy val 落在
   fp32 臂 +0.10 容差內（實測 +0.058）。

## 解讀

- **toy 尺度下 NVFP4 RTN 幾乎免費**（-0.005 nats，甚至是輕微 regularization 方向的
  雜訊）：16 寬 block + E4M3 block scale 對平滑收斂權重是很細的 grid，與
  case_quant_fused 的 RTN error oracle（NVFP4 0.0776 < MXFP4 0.1078）一致。
  因此 QAT 的「恢復力」在此尺度沒有東西可恢復——PTQ-vs-QAT delta 只記錄、不設閘。
  QAT 的保險價值在生產尺度（RTN 誤差隨模型規模與任務難度放大）才會顯現。
- QAT-from-scratch 在**相同步數預算**下收斂到 fp32 鄰域（+0.058），grid 的代價
  表現為收斂速度而非最終品質上限——這正是 QAT 的預期行為。

## 本次修的真 bug（parity oracle 的戰果）

MLA absorbed decode 路徑直接切 `kv_b_proj.weight`（`mla.py::_w_uk_w_uv`）做
W_UK/W_UV 吸收矩陣——`apply_qat` 包裝後該屬性是 fp32 **主權重**，直讀會繞過
fake-quant grid：module-call 路徑（prefill）走 grid、absorbed 路徑走 fp32，兩者在
bake/deploy 時分叉（實測 logits max diff 0.158）。修復：`FakeQuantLinear.ste_weight()`
提供「grid 值 + STE 梯度」的權重存取，`_w_uk_w_uv` 以 `hasattr` 回落——非 QAT 模型
行為 bitwise 不變。

## 誠實邊界（引用前必讀）

1. **單一 seed、240 步、toy 尺度**（8.5M、char 語料）：這是訓練迴圈與 deploy parity
   的 smoke，不是生產品質結論；多 seed 掃描是後續動作（腳本支援 `--seed`）。
2. 語料由 repo 當前 `*.py + *.md` 即時重建，repo 演進會平移絕對 val loss；
   同一 run 內三臂共用同一語料快照，比較不受影響（`stable_corpus` 雙讀一致才放行，
   防暫態讀取缺檔）。
3. 訓練 bitwise 可重現性以「同機器 + 同 torch build + 同執行緒數」為前提
   （同 hca_ab_passkey / mla_every_sweep 慣例）；gate 已在進程內雙跑驗證。
4. 曾評估 checkpoint 微調變體並**否決**：fresh optimizer 打在已收斂 toy checkpoint
   上，fp32 與 QAT 臂的 val 同步退化（optimizer 重啟病理，與量化無關），且收斂權重
   的 RTN 僅 +0.002 nats——無恢復空間。from-scratch 臂才是乾淨比較。
