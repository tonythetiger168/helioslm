# helioslm v5.4 — 全量掃尾修復報告

**日期:** 2026-09-12
**依據:** v5.3 的兩路獨立掃尾驗證(剩餘問題全掃描 + 系統性壓力測試,共發現 1 MAJOR + 2 MEDIUM + 8 LOW + 15 可選項)
**最終狀態:** 測試套件 **23/23 PASS**(exit 0);集成測試 **9/9 PASS**(exit 0);orchestrator 對最終磁盤狀態獨立核驗(關鍵修復 grep 確認 + 兩套件親跑)

---

## 一、MAJOR 修復

**B1 — Packed sequences 跨文檔注意力洩漏**(v5.3 對 M-C1 的修復在 packed 場景無效)
- `mla.py`:從 position_ids 重置點推導 `doc_id`(`pos[i] <= pos[i-1]` 處 cumsum 分段),causal mask = `same_doc & (k_pos <= q_pos)`。
- 附帶深度修復:實測發現即使注意力零洩漏,MoE 的 per-row GEMM 結果依賴 batch 行數(~1e-7 漂移),會使 packed 測試不穩——MoE dispatch 改為固定 64-row block,模型級擾動實驗 diff=0.0。
- 新增回歸測試 `test_packed_positions`(absorbed+expanded 雙模式,含反向 sanity 檢查)。

## 二、MEDIUM 修復

1. **引擎 `max_new_tokens=0` 仍生成 1 token**(`vllm_engine.py`):schedule 後新增第二輪 retire,已完成 request 不進 prefill;step 返回 `{}`。
2. **FP8 轉換破壞 MTP weight tying**(`fp8_trainer.py`):named_modules 按 identity 去重導致共享 lm_head 只換一次;轉換後防禦性重綁定(對齊 QuantizationManager 做法),`mtp_modules[i].lm_head is model.lm_head` 驗證通過。

## 三、LOW / 健壯性修復(全部處置)

- generate/MTP generate 的 eval() 改 try/finally 快照恢復(3 處)
- audio prefix 編碼前 `reset_state()`(消除串流狀態洩漏,兩次 forward diff=0.0)
- 空序列/負 position_ids/GRPO 空 prompts/AWQ 校准形狀錯誤/NaViT 小圖與空列表 → 全部改清晰 ValueError
- 引擎前向異常時失敗 request 釋塊 + error 態,引擎可繼續服務
- 引擎參數改從 config.paged_attention 讀取;LRU memo、num_rounds 計數、採樣改 torch.Generator(可復現)
- MoE local_experts 惰性緩存;RMSNorm 去重;config 校驗補齊(dropout 範圍/token id 範圍等 9 項);`assert bits` → ValueError;裸 Linear skip 加 warning;`_pad_prefix_cache` 註釋更正;`_recompute_stage` 註解修正;6 個空腳手架目錄刪除
- 版本字符串全部統一 v5.4(src/config/README/CHANGELOG;測試中的 v5.3 字樣為歷史註釋,正確保留)
